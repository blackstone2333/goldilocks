# Idea Ledger

New ideas are useful signals, not automatic scope.

Classify an idea when it appears:

1. **Required for current acceptance:** add it to the current task and update the relevant check.
2. **Changes the agreed end state:** pause the affected work, explain the consequence, and return to alignment before continuing.
3. **Valuable but not necessary now:** record it in the deferred idea ledger without interrupting delivery.

Default to a non-mutating entry in the final handoff. Update an existing local backlog, design note, or project ideas file only when the current task already authorizes that file write and it does not alter the delivered scope. Do not automatically create an external issue, message, ticket, or remote record merely because an idea appeared.

Create a new durable local ledger only when an idea actually appears, no suitable home exists, and the current task authorizes that additional artifact. For short sessions, the final handoff entry is enough.

Record only:

- the idea in one sentence;
- why it may be valuable;
- the evidence or trigger that would justify revisiting it;
- known dependency on the current work, if any.

Do not design or implement the deferred idea, add speculative scaffolding, or let it silently alter current acceptance. At completion, mention captured ideas separately from delivered scope.
