# Evolve

Preserve useful ideas without letting them silently expand the current project, and improve workflow rules only from evidence.

## Capture ideas proportionally

Classify each mid-flight idea:

1. Required for current acceptance: add it to scope and its checks.
2. Changes the agreed end state: pause the affected work and return to alignment.
3. Valuable but unnecessary now: record it as deferred without interrupting delivery.

Prefer a short final-handoff ledger. Update an existing local backlog or design note only when the task authorizes that write. Do not create external issues, messages, or tickets without explicit authority.

When an idea must survive the current session or the work already uses durable records, read [continuity.md](continuity.md) and append the minimum useful entry to the project's existing backlog or `docs/ideas.md`. Direct work keeps ideas in the final response.

Record the idea, value, revisit trigger, and dependency in a few lines. Do not design speculative implementation or scaffold deferred work.

## Write and improve skills empirically

Treat workflow documentation as behavior-changing code:

1. Define realistic trigger, positive, negative, pressure, and boundary scenarios.
2. Capture a no-guidance or previous-version baseline.
3. Record the exact observable failure or unnecessary process.
4. Add the smallest rule, reference, script, or metadata change that closes it.
5. Validate structure and rerun in a fresh context without leaking the expected answer.
6. Compare quality, authority, user rounds, agent calls, tokens, and elapsed time.

Use subagents for independent forward tests only when available and worth their cost. Static contracts are appropriate for deterministic structure; behavioral claims need fresh behavioral evidence.

Keep trigger descriptions specific, bodies concise, and detailed rules in one-level references loaded only when needed. Reuse scripts and assets instead of repeating instructions. Do not add universal ceremony because it sounds prudent; require a reproducible failure, preserve exceptions, and delete rules that add cost without observable quality value.

Validate every skill and its UI metadata before deployment. Separate project documentation from agent instructions, and remove placeholders, duplicated rules, stale references, and accidental auto-triggers.
