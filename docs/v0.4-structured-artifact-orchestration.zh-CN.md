# Goldilocks v0.4：结构化产物编排

Goldilocks v0.4 把软件项目中的公司式组织方法推广到所有“具有统一系统、又能拆成独立单元”的交付物。它负责组织生产，不会把自己变成 PPT、文档、表格或视频编辑器。

## 架构

`目标 → 全局产物合同 → 单元合同 → 并行生产 → 单元验收 → 局部返工 → 集成 → 全局验收 → 长期经验`

全局 Artifact Contract 会冻结受众与结果、文件格式、结构图、叙事/设计/数据系统、术语与来源、单元依赖、验收标准、合并顺序以及唯一集成人。随后，每个单元合同只外置一个可独立替换的最小交付单元。

Lead 负责用户意图、全局系统、共享接口、集成与最终验收；Standard 负责一个有边界的领域，例如 PPT 分镜，并可把已解决的局部决策转成 Fast 合同；Fast 只生产决策已经外置的单元或安全批次，并保持叶子成员。具体文件格式、渲染和格式修复仍由对应的专业 Skill 负责。

执行单元不等于 Agent 会话。一张失败的幻灯片或一个失败章节应当可以单独替换；若几个单元工具和上下文相同，也可以放进同一个工作会话，摊薄启动成本。易损的最终文件始终只有一名集成人可以修改。

## 渐进式加载

`artifact-production` 是一个很薄的入口，只加载一份通用协议和当前领域需要的 Profile。v0.4 先发布 Presentation Profile；只有真实项目暴露出新的领域编排问题时，才继续增加文档、表格或视频 Profile。入口、通用协议和演示文稿 Profile 的活动路径总预算低于 1,600 个英文词。

## 演示文稿 Profile

PPT 先有分镜，再有逐页合同。每页只有一个主要任务，并写清内容、活动、视觉方向、备注与来源、依赖、验收条件和批次。生产者不能并行修改最终 PPTX；唯一集成人负责组装已验收页面，逐页全尺寸检查，再用缩略图总览检查节奏。发现问题时执行 localized rework，只返工失败页面，最后验证完整文件。

## 首轮试验与发布口径

首轮试验是一份 12 页的 HSK4 一对一课程《网络购物：方便还是麻烦？》，用于验证合同完整性、领域规划、页面可替换性、唯一集成人、渲染验收与局部返工。它证明的是架构可执行，不代表 v0.4 已经在所有产物领域都更快、更省。后续实验应继续比较产物质量、昂贵 token 占比、总 token、耗时、用户往返、局部返工与集成缺陷。
