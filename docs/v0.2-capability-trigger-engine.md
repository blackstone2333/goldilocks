# Goldilocks v0.2 — Capability & Trigger Engine

## Goal

Replace Superpowers-level capability coverage with less mandatory process and less loaded context. Preserve capability and quality parity without ceremony parity.

## Capability engines

| Engine | Coverage |
|---|---|
| Align | Brainstorming, Grill frontier, design, requirements, authority boundaries |
| Diagnose | Systematic debugging, root cause, failed-hypothesis escalation |
| Build | Reuse/native-first, planning, TDD, implementation |
| Orchestrate | Worktrees, parallel work, capability routing, integration ownership |
| Prove | Review, verification, real runtime, branch finishing |
| Evolve | Idea ledger, skill writing, process improvement |

Align, Diagnose, Build, Orchestrate, and Prove each carry one conditional idea-capture route. It records useful out-of-scope ideas in the final handoff and loads Evolve only when an idea actually needs classification or durable storage.

## Compatibility entries

| Goldilocks entry | Shared engine |
|---|---|
| `brainstorming` | Align |
| `writing-plans`, `executing-plans`, `test-driven-development` | Build, plus Prove when executing |
| `systematic-debugging` | Diagnose + Prove |
| `using-git-worktrees`, `dispatching-parallel-agents`, `subagent-driven-development` | Orchestrate |
| `requesting-code-review`, `receiving-code-review`, `verification-before-completion`, `finishing-a-development-branch` | Prove |
| `writing-skills` | Evolve + Prove |

The explicit `goldilocks` router replaces `using-superpowers`. Its implicit invocation is disabled. Each compatibility entry routes into the relevant engine in no more than 80 body words.

## Hard budgets

- Main router: at most 650 words.
- Thin entry: at most 80 body words.
- Direct path: no Goldilocks skill unless explicitly requested.
- Ordinary feature path: at most 1,500 rule words at any stage.
- Single coherent workflow: zero agents by default.
- No material ambiguity: zero extra user rounds by default.
- All capability documentation: at most 6,000 words.
- Every added rule: backed by a reproducible failing evaluation.

## Evidence before expansion

The 52-case suite fixes expected routing and budgets. Static contracts cover deterministic structure; behavioral claims require fresh contexts without the expected answer or another arm's output. Failures are converted into the smallest engine, entry, or trigger change that closes the observed gap.
