# Goldilocks v0.2 — Capability & Trigger Engine

## Goal

Replace Superpowers-level capability coverage with less mandatory process and less loaded context. Preserve capability and quality parity without ceremony parity.

## Capability engines

| Engine | Coverage |
|---|---|
| Align | Brainstorming, Grill frontier, design, requirements, authority boundaries |
| Diagnose | Systematic debugging, root cause, failed-hypothesis escalation |
| Build | Reuse/native-first, planning, TDD, implementation |
| Orchestrate | Worktrees, parallel work, capability routing, integration ownership |
| Prove | Review, verification, real runtime, branch finishing |
| Evolve | Idea ledger, skill writing, process improvement |

Align, Diagnose, Build, Orchestrate, and Prove each carry one conditional idea-capture route. It records useful out-of-scope ideas in the final handoff and loads Evolve only when an idea actually needs classification or durable storage.

## Continuity protocol

Continuity is a shared, conditionally loaded protocol—not a seventh engine or another visible Skill. It preserves project knowledge only when the work earns persistence:

- Direct creates no workflow continuity record by default, while retaining normal documentation autonomy when docs are the deliverable or necessary for correctness.
- Guarded may use one compact work packet for multi-stage or cross-session work.
- Critical, Orchestrated, and substantial handoffs may split current spec, plan, and handoff.
- New projects and architecture-level changes record a project structure contract before implementation.

Goldilocks follows existing repository conventions first. Its neutral fallback uses `docs/PROJECT.md`, `docs/work/`, `docs/decisions/`, `docs/debug/`, `docs/ideas.md`, and a user-facing root `CHANGELOG.md`. Three optional zero-context templates cover a project map, work packet, and debug note; empty sections are removed rather than filled ceremonially.

The debug memory is selective: search old notes before repeating investigation, revalidate old workarounds, add regression coverage after a fix when practical, and record only reusable non-obvious root causes or traps. Internal debug history never pollutes the release changelog.

## Parallel and model routing

After a multi-unit plan, Orchestrate performs a routing pass before the Lead starts implementing everything. Two or more meaningful independent units default to parallel execution when setup and review do not erase the saving; eligible serial execution records its reason. Fast workers receive mechanical implementation, fixtures, test authoring, focused checks, and read-heavy exploration. The Lead keeps architecture, complex shared logic, review, integration, and the fresh combined acceptance gate.

When multiple models or billing channels exist, the shared model-routing protocol applies task-specific quality gates, confidence and recency discounts, expected cost per successful delivery, and a Pareto quality/cost/latency shortlist. Codex Pro prefers `gpt-5.3-codex-spark` for eligible Fast text-only work when its separate usage limits are available. The dated public model registry is advisory and yields to current host availability and local evidence.

## Compatibility entries

| Goldilocks entry | Shared engine |
|---|---|
| `brainstorming` | Align |
| `writing-plans`, `executing-plans`, `test-driven-development` | Build, plus Prove when executing |
| `systematic-debugging` | Diagnose + Prove |
| `using-git-worktrees`, `dispatching-parallel-agents`, `subagent-driven-development` | Orchestrate |
| `requesting-code-review`, `receiving-code-review`, `verification-before-completion`, `finishing-a-development-branch` | Prove |
| `writing-skills` | Evolve + Prove |

The explicit `goldilocks` router replaces `using-superpowers`. Its implicit invocation is disabled. Each compatibility entry routes into the relevant engine in no more than 80 body words.

## Hard budgets

- Main router: at most 650 words.
- Thin entry: at most 80 body words.
- Direct path: no Goldilocks skill unless explicitly requested; completion wording alone does not trigger Prove, and an explicit verification entry degrades to one targeted inline check.
- Ordinary feature path: at most 1,500 rule words at any stage.
- Single coherent workflow: zero agents by default.
- No material ambiguity: zero extra user rounds by default.
- All capability documentation: at most 6,000 words.
- Visible workflow surface: fourteen Skills and six engines; continuity must remain a shared protocol.
- Model routing remains a shared protocol and dated asset, not another visible Skill or universal winner list.
- Every added rule: backed by a reproducible failing evaluation.

## Evidence before expansion

The 53-case suite fixes expected routing and budgets. Static contracts cover deterministic structure; behavioral claims require fresh contexts without the expected answer or another arm's output. Failures are converted into the smallest engine, entry, or trigger change that closes the observed gap.
