# Goldilocks v0.3: Hierarchical Orchestration

[简体中文](v0.3-hierarchical-orchestration.zh-CN.md)

v0.3 changes Goldilocks from a one-level workflow router into a dynamic organization protocol. The user owns direction and acceptance. Lead owns intent, architecture, resource allocation, shared interfaces, and final quality. Standard owns one bounded domain and may delegate complete execution contracts to Fast. Fast implements and runs focused checks but is a leaf.

## Routing order

1. Search a verified route for the same project task shape.
2. Run a constant-time make-or-delegate check.
3. Resolve product, architecture, authority, and shared-interface decisions at Lead.
4. Choose the shallowest useful shape: Direct, Lead→Fast, Lead→Standard, or Lead→Standard→Fast.
5. Run every independent ready node allowed by host capacity, isolation, integration risk, and reviewer throughput.
6. Integrate evidence upward; Lead reruns the combined gate.
7. Preserve the route only after combined verification and only when recurrence is plausible.

Role selection happens after decomposition. Fast means low residual discretion, not a small diff. Standard means bounded local judgment, not a medium task. Lead means authority and final accountability, not an obligation to implement everything.

## Economic objective

Quality, safety, authority, and tool compatibility are hard gates. Valid routes are compared by:

- quota-weighted expensive usage, using current account coefficients and channel scarcity when known;
- wall-clock critical path;
- total raw-token growth relative to Direct or a verified similar route;
- retry, review, and integration debt.

A route may spend slightly more low-coefficient or separately metered worker tokens when it materially reduces scarce Lead quota or elapsed time without weakening quality. Missing quota evidence remains unknown; Goldilocks never invents coefficients.

## Context and escalation

Fast normally receives no parent turns and one self-contained contract. Standard receives the domain contract plus no more than four relevant turns. An explicit Lead handoff may inherit full history and the parent Lead model when critical decisions remain distributed across the conversation.

One bounded repair is allowed. A second failure or requirement mismatch ends the worker loop and triggers reclassification or local ownership. Standard cannot change shared interfaces or expand authority. Multiple Standard advisers may inspect a difficult decision, but one owner decides and integrates.

## Codex dual worker routes

Codex routing must reflect the model actually available on the selected execution path:

1. Use native subagents for a host-advertised model. Every call declares `fast__`, `standard__`, or `lead__`, sets `fork_turns` explicitly, and selects a model explicitly except for justified full-history Lead inheritance.
2. When the selected eligible Fast model is omitted by the native model list but available to `codex exec`, use the packaged `dispatch_codex_worker.py` in the Goldilocks Skill. The current adapter maps `coding` to GPT-5.3-Codex-Spark and `general` non-coding production to GPT-5.6 Luna.
3. If neither route clears the capability and quality gates, deliberately reclassify to another Fast model, Standard, or local ownership. Never silently inherit Lead.

The external adapter reads one complete contract from a file, sends it to Codex over stdin, fixes the model from the declared work type, and disables only further agent spawning. Its default `project` profile uses a clean worker home that excludes unrelated global plugins, Apps, MCP, Skills, and Hooks while preserving repository rules, authentication, provider selection, model metadata, and the bundled runtime. `minimal` also ignores execpolicy rules; `inherit` retains the user's full environment only when the contract explicitly requires it. The adapter limits its sandbox to read-only or workspace-write and propagates the worker exit code. Parallel writers still require isolated worktrees. Lead or Standard reviews actual diffs and evidence; a successful process exit alone is not acceptance.

Fast remains an organizational role rather than a model alias. Spark is the coding default; Luna is the general non-coding production default. A replaceable unit also does not imply a separate worker startup: begin with one coherent batch when route economics are unknown, and add sessions only when measured parallel savings repay their context and review cost.

This distinction is evidence-driven. On 2026-07-25, the installed Codex `0.146.0-alpha.3.1` native collaboration tool exposed Sol and Terra only, while its bundled CLI successfully launched the exact Spark model. Earlier `0.144.0-alpha.4` logs contained 22 real `codex_exec` Spark worker sessions. This proves the dual-route need for that host range, not a permanent promise about future model catalogs.

## Execution memory and audit

Project execution patterns store verified routes, preconditions, invalidators, role structure, model classes, evidence, retries, elapsed time, and quota/raw-token observations when known. They never store prompts, credentials, private data, or raw logs, and they never replace the user-facing changelog.

The Codex hook stores anonymous native-route observations in `PLUGIN_DATA/orchestration.db`. SQLite prevents concurrent-write corruption. A start is audited only when correlation is unique; ambiguity is recorded without accusing or stopping a specific child. Specialized native paths may bypass `PreToolUse`, so an unplanned Sol child gets a soft make-or-return check at `SubagentStart`. Observed completion is not a verified pass.

## Release acceptance

The orchestration layer is structurally complete when deterministic contracts pass for nested routing, context boundaries, Fast leaf enforcement, concurrency-safe audit, version metadata, the single visible Skill, and all internal engine routes. Performance success still requires real-project non-inferiority evidence: unchanged acceptance quality, lower Lead quota share, bounded raw-token change, shorter critical path where parallelism exists, and no increase in integration defects.
