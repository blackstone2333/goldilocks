# Goldilocks v0.4: Structured Artifact Orchestration

Goldilocks v0.4 applies the company-style organization from software projects to any deliverable that has a shared system and separable units. It coordinates production; it does not become a presentation, document, spreadsheet, or video editor itself.

## Architecture

`Goal → Global Artifact Contract → Unit Contracts → Parallel Production → Unit QA → Localized Rework → Integration → Global QA → Durable Lessons`

The Global Artifact Contract freezes the audience and outcome, format, structure map, narrative/style/data system, terminology and sources, unit graph, acceptance rubric, merge order, and one integration owner. Unit contracts then externalize the smallest independently replaceable pieces.

Lead owns intent, the global system, shared interfaces, integration, and final acceptance. Standard owns a bounded domain such as a deck storyboard and may turn its decisions into Fast contracts. Fast produces already-decided units or safe batches and remains a leaf. The production skill for the selected format owns file APIs, rendering, and format-specific repair.

Execution units are deliberately smaller than worker sessions. One failed slide or section can be replaced without rebuilding its neighbours, while several similarly tooled independent units can share one worker session to amortize startup context. Exactly one integration owner mutates the canonical fragile artifact.

## Progressive disclosure

In v0.4.1, Artifacts is an explicit internal route of the single `goldilocks` Skill. It loads only the generic protocol and relevant domain profile. The Presentation Profile remains the first profile, and later profiles should be added only after real work exposes a domain-specific orchestration failure. The router, generic protocol, and presentation profile stay below a 1,600-word active-route budget.

## Presentation profile

A presentation begins with a storyboard and one-slide contracts. Each slide keeps one primary job, its own content/activity/visual brief, notes and source policy, dependencies, acceptance checks, and batch assignment. Producers do not concurrently edit the final PPTX. The integration owner assembles accepted units, inspects every slide full-size, uses a montage for global rhythm, repairs only failed slides, and validates the final file.

## Pilot and release claim

The initial pilot is a 12-slide HSK4 one-to-one lesson, “网络购物：方便还是麻烦？”. It tests contract completeness, domain planning, unit replaceability, integration ownership, render QA, and localized rework. It is architecture evidence, not a broad claim that v0.4 is faster or cheaper in every artifact domain. Future experiments should compare artifact quality, expensive-token share, raw tokens, elapsed time, user rounds, localized rework, and integration defects.
